# openCenter CLI v1.0.0-rc03 -- Release Notes

> **Purpose:** For operators and platform engineers, lists features, fixes, and improvements shipped in openCenter CLI 1.0.0-rc03.

---

## Overview

Third release candidate for openCenter CLI 1.0.0. This release introduces release-tag pinning for the base services GitRepository source, fixes a false-positive legacy layout detection that blocked freshly initialized clusters, completes the AsciiDoc-to-Markdown documentation migration, and adds gitleaks pre-commit scanning.

---

## Highlights

* **Release-Pinned GitOps Sources** -- Base services repository now references a tag instead of a branch when `base_repo.release` is configured
* **Legacy Layout Detection Fix** -- Freshly initialized clusters no longer trigger a false LegacyLayoutError
* **Documentation Migration Complete** -- All AsciiDoc content converted to Markdown; Antora scaffolding removed
* **Gitleaks Integration** -- Pre-commit secret scanning with allowlisted docs, tests, and false positives
* **Calico 3.31.6** -- Default CNI version bumped to latest patch

---

## New Features

### Release Tag for Base Repository Source

When `base_repo.release` is set in the GitOps configuration, the generated FluxCD `GitRepository` source now uses `ref.tag` instead of `ref.branch`. This enables deterministic, version-pinned deployments of the base services library.

Default behavior:
- **Cluster GitOps repository** -- branch tracking (mutable, follows HEAD)
- **Base services repository** -- release-pinned tag (immutable, explicit upgrade)

The manifest validator accepts both `branch` and `tag` as valid ref types in GitRepository resources.

---

## Bug Fixes

* **Branch/tag mutual exclusivity** -- `RepoBranch` is now cleared when a release tag is set in the auto service context. FluxCD `GitRepository` sources previously rendered with both `ref/branch` and `ref/tag`, causing reconciliation failures.

* **Legacy layout false positive** -- The presence of `infrastructure/clusters/<name>` inside a `.git`-containing org directory is expected for a valid GitOps repository. Only `secrets/` or `.<cluster>-config.yaml` co-located in the org root now trigger legacy detection. Regression tests added.

* **DefaultStorageClass template path** -- Mimir and vSphere-CSI override-values templates referenced `.OpenCenter.Storage.DefaultStorageClass` (non-existent). Corrected to `.OpenCenter.Infrastructure.Storage.DefaultStorageClass`.

* **Calico version default** -- Bumped from 3.29.x to 3.31.6 to match current stable release.

## Known Limitations

* AWS provider support is planned but not yet implemented
* ArgoCD integration is in progress (FluxCD is fully supported)
* Air-gapped deployment requires the separate openCenter-AirGap package
* Windows worker node support requires the separate opencenter-windows package

## Upgrade from rc02

No configuration file changes required.

```bash
# Rebuild from source
mise run build

# Verify
./bin/opencenter version
./bin/opencenter cluster validate <name>
```

If you previously set `base_repo.release` in your GitOps configuration, regenerate to pick up the tag-pinned source:

```bash
./bin/opencenter cluster generate <name>
```
