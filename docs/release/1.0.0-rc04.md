# openCenter CLI v1.0.0-rc04 -- Release Notes

> **Purpose:** For operators and platform engineers, lists features, fixes, and improvements shipped in openCenter CLI 1.0.0-rc04.

---

## Overview

Fourth release candidate for openCenter CLI 1.0.0. This release adds the OpenStack cluster sync command, introduces GitOps auth selection with base secret reconciliation, fixes several GitOps manifest issues (Gateway listeners, Kustomization spec), aligns observability overrides with the restructured base repo, and deduplicates SOPS overlay encryption logic.

---

## Highlights

* **OpenStack Sync Command** -- New `cluster sync` subcommand for OpenStack-backed clusters
* **GitOps Auth Selection** -- Interactive auth method selection and base secret reconciliation during cluster generation
* **Gateway Listener Fix** -- The `longhorn-https` listener is now included in HTTPRoute-dependent Gateway manifests
* **Flux Kustomization Cleanup** -- Removed invalid `spec.cluster` field from generated Kustomizations
* **Config Registry Alignment** -- Default service map types now match the config registry definitions
* **Observability Restructure** -- CLI overrides aligned with the reorganized base repo observability layout

---

## New Features

### OpenStack Sync Command

Added `opencenter cluster sync` support for OpenStack provider. Operators can now synchronize cluster state from an OpenStack environment, keeping local configuration in lockstep with remote infrastructure.

### GitOps Auth Selection and Base Secret Reconciliation

Cluster generation now prompts for the GitOps authentication method (SSH, HTTPS token, etc.) and automatically reconciles the required base secrets. This removes manual secret scaffolding steps from the operator workflow.

---

## Bug Fixes

* **longhorn-https Gateway listener** -- HTTPRoutes requiring the `longhorn-https` listener now have the corresponding Gateway listener generated. Previously, the listener was omitted causing routing failures for Longhorn UI access over HTTPS.

* **Flux Kustomization spec.cluster** -- Generated Flux `Kustomization` resources no longer include the invalid `spec.cluster` field. FluxCD does not recognize this field and logged warnings during reconciliation.

* **Config registry type alignment** -- Default service map entries now use the types defined in the config registry, preventing type-mismatch validation errors on freshly initialized clusters.

* **Observability CLI overrides** -- Override-values paths updated to reflect the base repository restructure (moved from flat layout to domain-grouped directories). Clusters using observability features no longer fail generation with missing template errors.

* **Baremetal template defaults** -- Updated default values in the baremetal cluster template to match current infrastructure expectations.

---

## Refactoring

* **SOPS overlay deduplication** -- Encryption file selection logic for overlays consolidated into a single code path, reducing maintenance surface and eliminating subtle behavioral differences between providers.

## Known Limitations

* AWS provider support is planned but not yet implemented
* ArgoCD integration is in progress (FluxCD is fully supported)
* Air-gapped deployment requires the separate openCenter-AirGap package
* Windows worker node support requires the separate opencenter-windows package

## Upgrade from rc03

No configuration file changes required.

```bash
# Rebuild from source
mise run build

# Verify
./bin/opencenter version
./bin/opencenter cluster validate <name>
```

If you use observability features, regenerate your cluster manifests to pick up the corrected override paths:

```bash
./bin/opencenter cluster generate <name>
```
