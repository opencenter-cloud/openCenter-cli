# openCenter CLI v1.0.0-rc05 -- Release Notes

> **Purpose:** For operators and platform engineers, lists features, fixes, and improvements shipped in openCenter CLI 1.0.0-rc05.

---

## Overview

Fifth release candidate for openCenter CLI 1.0.0. This release introduces provider-agnostic configuration validation with helpful hints, adds the `vip_interface` networking field, fixes the missing SOPS Age secret during cluster deploy, resolves YAML quoting issues in GitRepository source manifests, and improves OpenStack multi-subnet handling.

---

## Highlights

* **Provider-Agnostic Validation** -- Cross-field validation for all providers with "Did you mean?" suggestions and Levenshtein-based field matching
* **VIP Interface Field** -- New `vip_interface` field for kube-vip interface binding with VRRP validation warnings
* **SOPS Age Secret Bootstrap** -- The sops-age Kubernetes Secret is now automatically created during cluster deploy
* **GitRepository Ref Quoting** -- Numeric-looking release tags are now properly quoted in generated YAML
* **OpenStack Multi-Subnet Fix** -- Graceful handling when multiple subnets are discovered without an explicit override

---

## New Features

### VIP Interface Field and Provider-Agnostic Validation

Added `vip_interface` to `NetworkingConfig` for explicit kube-vip interface binding. Introduced comprehensive cross-field validation for all supported providers:

- **Baremetal** -- Validates `master_nodes`/`worker_nodes`, `StaticNode` fields, and count mismatches
- **VMware** -- Requires `cloud.vmware` fields; warns if `vsphere_csi` is not enabled
- **Kind** -- Enforces bastion disabled, kube-vip disabled, VRRP disabled
- **AWS/GCP/Azure** -- Requires provider-specific cloud section with key fields

Validation errors now include intelligent suggestions:
- Detects provider names incorrectly used as config sections
- Suggests close field name matches using Levenshtein distance
- Shows valid fields when no close match exists
- Displays suggestions inline with errors in grouped output format

A `NetworkValidator` warning is emitted when VRRP is enabled without `vip_interface` set.

## Bug Fixes

* **SOPS Age secret missing during deploy** -- The sops-age Kubernetes Secret referenced by every Flux Kustomization with SOPS decryption was never created in the cluster. A new bootstrap step (`reconcile-sops-age-secret`) now reads the local Age private key and applies it as a Secret in `flux-system` during cluster deploy. Registered for all providers. Additionally, the post-deploy next-steps message now prints the correct command (`opencenter secrets sync <name>` instead of the non-existent `opencenter cluster secrets sync <name>`). Fixes: OCTR-604.

* **GitRepository ref values not quoted** -- `RenderSourceAuthBlock` was emitting `spec.ref.tag` (and branch) values without YAML quotes. Numeric-looking release tags (e.g., `2026.01`) were parsed as floats by YAML, causing Flux server-side dry-run validation to reject every GitRepository object. All ref values are now double-quoted in generated YAML. Fixes: OCTR-603.

* **OpenStack multi-subnet handling** -- Subnet selection now gracefully skips when multiple subnets are discovered and no explicit subnet ID is provided, allowing deployment to create a new subnet instead of erroring out.

## Upgrade from rc04

No configuration file changes required. If you use the new `vip_interface` field, add it to your cluster configuration under `networking`:

```yaml
networking:
  vip_interface: "eth0"  # optional, for explicit kube-vip interface binding
```

```bash
# Rebuild from source
mise run build

# Verify
./bin/opencenter version
./bin/opencenter cluster validate <name>
```

If you previously deployed clusters that use SOPS decryption, the sops-age secret is now created automatically. For existing clusters, redeploy or manually apply the secret:

```bash
./bin/opencenter cluster deploy <name>
```

Regenerate GitOps manifests to pick up the quoted ref values fix:

```bash
./bin/opencenter cluster generate <name>
```
