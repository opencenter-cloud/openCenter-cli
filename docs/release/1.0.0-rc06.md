# openCenter CLI v1.0.0-rc06 -- Release Notes

> **Purpose:** For operators and platform engineers, lists features, fixes, migrations, and improvements shipped in openCenter CLI 1.0.0-rc06.

---

## Overview

The sixth release candidate for openCenter CLI 1.0.0 focuses on safe, repeatable cluster generation and production-readiness across OpenStack and the platform-service catalog. It adds transactional, ownership-aware GitOps promotion; hardens the complete SOPS Age key lifecycle; replaces the monolithic OpenStack sync flow with explicit provider and per-service storage plan/apply operations; and resolves deployment ordering, storage, authentication, and secret-materialization failures found during end-to-end cluster testing.

This release contains 105 commits since rc05.

---

## Highlights

* **Ownership-safe GitOps generation** -- Generation is staged and promoted transactionally, refuses to overwrite modified or unknown files, tracks generated and secret artifacts, and preserves user content under `custom/`.
* **Hardened Age key lifecycle** -- Multiple active recipients, explicit primary-key selection, recipient reconciliation, atomic rotation, and lockout-safe revocation are now enforced.
* **OpenStack plan/apply workflows** -- Provider discovery and service storage provisioning are separate, reviewable operations with structured output and support for OpenTofu-managed internal networking.
* **Platform-service deployment reliability** -- Flux ordering and configuration fixes cover Keycloak, OLM, Harbor, Mimir, Loki, Tempo, etcd-backup, Sealed Secrets, cert-manager, Longhorn, Kafka, and monitoring.
* **Safer public source authentication** -- Public openCenter base repositories are fetched anonymously while private customer GitOps sources continue to use their configured credentials.
* **Disposable Kind deployment CI** -- A new workflow exercises cluster generation and deployment in an isolated Kind environment.

## New Features and Improvements

### Transactional GitOps Generation and Ownership

Cluster generation now builds in a staging workspace, validates the complete tree, and promotes it only after all checks pass. The generated-file manifest records hashes and ownership so subsequent runs can distinguish safe updates from user edits. Modified tracked files and conflicting untracked files fail closed instead of being silently overwritten.

Secret artifacts use a separate deterministic ownership ledger. Scoped service renders refresh aggregate Kustomizations, and `secrets sync` refreshes manifests after materializing encrypted `secret.yaml` files so those files are included in their parent Kustomizations.

### SOPS Age Key and Secret Management

The key registry now supports multiple active Age recipients and one explicit primary key. New commands provide primary selection and reconciliation between registry state and `.sops.yaml`:

```bash
opencenter secrets keys reconcile --cluster <name>
opencenter secrets keys reconcile --cluster <name> --apply
opencenter secrets keys set-primary --cluster <name> --type age --fingerprint <fingerprint>
```

Reconciliation is report-only by default. Applying it imports missing active recipients without deleting registry entries or rewriting `.sops.yaml`. Rotation and revocation use atomic updates, preserve all remaining active recipients, reject registry drift that could cause data loss, and prevent removal of the only reachable decryption key.

### OpenStack Provider and Storage Operations

OpenStack configuration is now split into explicit operations:

```bash
opencenter cluster provider openstack plan <name> --os-cloud <profile>
opencenter cluster provider openstack apply <name> --os-cloud <profile>
opencenter cluster service storage plan <service> --cluster <name>
opencenter cluster service storage apply <service> --cluster <name>
```

Provider operations discover images, networks, subnets, availability zones, and optional authentication/TLS settings without creating cloud resources. Use `--create-internal-network` when the generated OpenTofu configuration should own the internal network and subnet. Per-service storage operations provision and wire supported object-storage backends independently.

### Typed Service Rendering Contract

Service rendering now comes from an internal immutable catalog rather than cluster-controlled renderer metadata. Public cluster configuration is serialized through typed service fields, while user-authored manifests and unsupported values belong in each service overlay `custom/` directory. Schema and documentation drift tests now guard the public configuration contract.

## Bug Fixes

### GitOps, Flux, and Bootstrap

* Fetch public openCenter base Git repositories anonymously, avoiding HTTP 401 failures caused by attaching an unrelated token.
* Refresh generated manifests after secret synchronization and after scoped auto-service renders.
* Restore the Flux bridge and etcd-backup aggregate entries so enabled services reconcile.
* Fix dependency deadlocks for Mimir, Sealed Secrets, Keycloak, Kyverno, and other staged services.
* Preserve namespaces in OLM manifests, create service namespaces before overrides, and add required OLM API and bundle-unpack network policies.
* Encrypt only secret payload values and sensitive service overrides, including nested secret maps.
* Always initialize OpenTofu even when prior state exists, and improve missing-SOPS diagnostics.

### Platform Services

* **Keycloak** -- Install the operator with automatic approval in a dedicated namespace and OperatorGroup, order PostgreSQL before Keycloak, correct startup defaults, and stop requiring an unused secret.
* **Harbor** -- Use dedicated OpenStack EC2 credentials for S3, secure credential materialization, improve namespace reconciliation, and set Cinder-compatible 10 Gi defaults for jobservice, Redis, and Trivy PVCs.
* **Mimir** -- Use the shared Kafka service, disable bundled Kafka and MinIO, support Swift block storage, fail fast on placeholder credentials, disable usage statistics, and increase persistent volumes to 10 Gi.
* **Loki and Tempo** -- Correct Loki native Swift authentication and DNS configuration; fix Tempo S3 endpoints, disable usage reporting, and reject unsupported Tempo Swift storage.
* **Storage and backup** -- Prevent Longhorn from taking over the cluster default StorageClass, pin observability and Kafka PVC StorageClasses, restore etcd-backup deployment, and correct provider-specific Velero values.
* **cert-manager and Sealed Secrets** -- Wire generated secrets into Kustomizations and remove namespace/dependency deadlocks.

### Infrastructure and Networking

* Propagate `networking.vip_interface` through provider inventories to kube-vip.
* Pin Kubespray node bind addresses and stop hardcoding bastion addresses.
* Correct OpenStack CSI generation and namespace security labels.
* Make provider and region default lookup case-insensitive.
* Pin the Calico chart and apply required operator CRDs before installation.

### Quality and Security

* Upgrade Go and dependencies to clear vulnerability-scanner findings.
* Stabilize race tests and provision SOPS in CI.
* Add regression coverage for staged generation, ownership, secret refresh, storage contracts, service dependency ordering, OpenStack discovery, and provider-specific rendering.
* Refresh generated CLI references, architecture maps, schema documentation, and workflow guidance.

## Breaking and Compatibility Changes

* **OpenStack sync command replaced** -- `opencenter cluster sync openstack` has been removed. Use `cluster provider openstack plan/apply` for provider metadata and `cluster service storage plan/apply` for each service storage backend.
* **Service image and source fields are nested** -- Replace `image_repository` and `image_tag` with `image.repository` and `image.tag`. Replace `gitops_source_repo`, `gitops_source_branch`, and `gitops_source_release` with `source.repo`, `source.branch`, and `source.release`.
* **Renderer internals are not public configuration** -- Legacy keys such as `renderer`, `single_stage`, `base_only`, `source_name`, `override_values_renderer`, `overlay_files_renderer`, and raw `override_values` are deprecated and removed during normalization.
* **Generation enforces ownership** -- User-authored files in generator-owned paths now stop generation. Move them into the service `custom/` directory or use the custom layout migration before regenerating.

## Upgrade from rc05

1. Back up cluster configuration, GitOps repositories, and Age private keys.
2. Normalize each legacy cluster configuration, then review and validate it:

   ```bash
   opencenter cluster normalize <name> --dry-run
   opencenter cluster normalize <name>
   opencenter cluster validate <name>
   ```

3. Reconcile SOPS recipients before rotating or revoking any Age key:

   ```bash
   opencenter secrets keys reconcile --cluster <name>
   opencenter secrets keys reconcile --cluster <name> --apply
   ```

4. For OpenStack clusters, replace previous sync automation with provider plan/apply and explicit per-service storage operations.
5. Preview generation. If ownership conflicts identify hand-authored overlay files, preview and apply the custom migration before retrying:

   ```bash
   opencenter cluster generate <name> --dry-run
   opencenter cluster migrate-layout --custom --org <org> --cluster <name>
   opencenter cluster migrate-layout --custom --org <org> --cluster <name> --apply
   ```

6. Regenerate, synchronize secrets, and deploy:

   ```bash
   opencenter cluster generate <name>
   opencenter secrets sync <name>
   opencenter cluster deploy <name>
   ```

## Known Limitations

* This is a release candidate intended for testing and validation, not a final GA release.
* Tempo does not support Swift storage in rc06; configure its supported S3-compatible backend instead.
* Public shared base sources use anonymous access. Private customer GitOps repositories still require correctly configured Flux credentials.
* Legacy hand-authored files outside `custom/` require explicit migration before ownership-safe generation can proceed.
