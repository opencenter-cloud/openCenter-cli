# openCenter CLI v1.0.0-rc07 -- Release Notes

> **Purpose:** For operators and platform engineers, lists features, fixes, migrations, and improvements shipped in openCenter CLI 1.0.0-rc07.

---

## Overview

The seventh release candidate for openCenter CLI 1.0.0 advances the platform lifecycle contract to v3, synchronizes upstream `openCenter-gitops-base` dependencies to `2026.03-rc05`, introduces automatic OpenTofu network output binding for OpenStack Cloud Controller Manager (CCM) integration, adds managed cluster support with the OpenStack Magnum provider, and delivers major resilience improvements across bootstrap resume state, resource cleanup, cert-manager DNS automation, and secrets management.

This release contains 173 commits since rc06.

---

## Highlights

* **Lifecycle Contract v3 & Automatic Network Binding** -- Advance Kubespray and infrastructure modules to contract v3; OpenTofu-created tenant networks and subnets are discovered and bound automatically into configuration post-apply, allowing CCM to configure Octavia load balancers without manual entry.
* **OpenStack Magnum Managed Provider** -- Added native managed Kubernetes cluster support backed by OpenStack Magnum with support for both application credentials and password authentication.
* **Streamlined OpenStack Init** -- `cluster init` binds OpenStack provider in one step via `--os-cloud`, automatically mints application credentials, discovers images, and sets sensible defaults.
* **Base Domain Provenance & Settings Sync** -- Seed base domain with `--base-domain` during initialization, track provenance across cluster updates, and synchronize global settings using `cluster set --follow-settings`.
* **Cert-Manager & Cloudflare DNS Automation** -- Render ClusterIssuer and credential Secrets directly from `dns_provider`, defaulting to Cloudflare with `--default` issuer pinning.
* **Resource Cleanup on Destroy** -- Automatically delete cluster-owned Octavia load balancers and orphan Cinder persistent volumes during `cluster destroy`, with `--skip-cluster-access` for unreachable endpoints.
* **Bootstrap Resume State & Scoped Directories** -- Scoped bootstrap resume state by cluster generation to safely resume interrupted deployments without re-executing completed stages.

## New Features and Improvements

### Lifecycle Contract v3 & Network Binding

Release candidate 07 introduces lifecycle contract v3, advancing the coordination between `openCenter-cli` and `openCenter-gitops-base`:

* **Contract v3 Outputs** -- The `openstack-nova` module now exports `opencenter_network_id` and `opencenter_subnet_id`.
* **Automatic Output Binding** -- The bootstrap pipeline introduces a `bind-network-outputs` step that queries OpenTofu outputs via the lifecycle command runner and writes the resolved network and subnet IDs directly into the cluster configuration.
* **Octavia CCM Integration** -- Cloud Controller Manager (CCM) receives the effective subnet ID dynamically, eliminating manual configuration and preventing Octavia VIP allocation failures on multi-subnet topologies.
* **Contract Upgrade Detection** -- The configuration loader detects contract gaps on older cluster configurations and emits advisory upgrade notices during validation.

### OpenStack Magnum Managed Provider

openCenter CLI now supports managed Kubernetes clusters through OpenStack Magnum (`provider: magnum`):

* Supports both Keystone application credentials and Keystone v3 password authentication.
* Skips OpenTofu VM orchestration, delegating node lifecycle directly to OpenStack Magnum cluster templates.
* Integrates with existing GitOps generation pipelines for seamless platform service delivery on top of Magnum clusters.

### OpenStack Provider Automation

* **One-Step Init via `--os-cloud`** -- Initialize OpenStack clusters in a single command (`opencenter cluster init <name> --os-cloud <profile>`), reading cloud configuration from `clouds.yaml`.
* **Automatic Application Credential Minting** -- Automatically mints Keystone application credentials during non-dry-run initialization, removing manual cloud credential provisioning.
* **Live Validation** -- Validates Nova compute flavors and Glance images against live OpenStack APIs during planning, surfacing missing or incompatible flavors early.
* **Soft Anti-Affinity Defaults** -- Worker server groups default to soft anti-affinity policies for improved cluster availability across hypervisors.
* **Deployment Preflights** -- Validates Keystone credentials before initiating provisioning, waits for Cloud Controller Manager availability, and reports comprehensive readiness status.

### Drift Reconcile, Observe, and Config Recovery

* **Observe & Recover** -- Discovers deployed infrastructure and live OpenTofu outputs, reconciling them back into cluster configuration.
* **Unified Drift Reconcile** -- Consolidated promote functionality into `opencenter cluster drift reconcile --to-config` to reconcile live infrastructure drift into declarative configuration files safely.

### Base Domain Provenance and Settings Synchronization

* **Initial Seeding** -- Seed cluster base domain during creation with `opencenter cluster init <name> --base-domain <domain>`.
* **Provenance Tracking** -- The cluster generator tracks whether the base domain originated from CLI flags, settings defaults, or manual overrides.
* **Settings Sync** -- Use `opencenter cluster set <name> --follow-settings` to synchronize domain changes from global CLI settings.

### Cert-Manager & Cloudflare DNS Automation

* **DNS Provider Declarations** -- Configure `dns_provider: cloudflare` in cluster networking to automatically generate cert-manager ClusterIssuer manifests and corresponding API token Secrets.
* **Default Issuer Pin** -- Added `--default` issuer flag to set default ingress certificate issuers.
* **Hostname Derivation** -- Automatically re-derives platform service hostnames from `cluster_fqdn`.
* **ACME Opt-Out** -- Allows clusters in disconnected or private networks to opt out of ACME challenge workflows.

### Cluster Destroy Hardening

* **Load Balancer Cleanup** -- Automatically tracks and purges Octavia load balancers owned by cluster Kubernetes services (OCTR-830).
* **Cinder Volume Cleanup** -- Identifies and deletes orphaned CSI Cinder persistent volumes during teardown (OCTR-800).
* **`--skip-cluster-access`** -- Allows destroying underlying cloud infrastructure when Kubernetes API server endpoints are unreachable or shut down.
* **Scoped Directory Removal** -- Protects shared GitOps repositories by strictly scoping `--remove-files` to designated cluster subdirectories.

### Bootstrap Resilience & Directory Isolation

* **Generation-Scoped Resume State** -- Bootstrap checkpoint state is partitioned by cluster generation and verified against disk artifacts, allowing interrupted deployments to resume safely without repeating completed steps.
* **Shared Temp Isolation** -- GitOps workspace temporary directories are scoped by Linux UID (`/tmp/opencenter-<uid>/...`) to prevent permission collisions on multi-user bastion hosts.

## Bug Fixes and Catalog Refinements

### Secrets Management
* Synchronize repository `.sops.yaml` creation rules during `secrets sync`.
* Name dedicated Secrets after their path to prevent collision and ensure proper manifest resolution.
* Automatically reconcile the `sops-age` Secret before the Cloud Controller Manager (CCM) gate during `cluster deploy`.
* Allow `--force` flag in secrets commands to adopt unowned cert-manager credential artifacts.
* Closed credential leak vectors and fixed Grafana OAuth secret naming discrepancies.

### Deployment & GitOps Pipeline
* Health check Cloud Controller Manager HelmRelease using its canonical release name.
* Reconcile local Gitea certificates and sanitize certificate Subject Alternative Names (SANs) for Kind provider.
* Support GitHub as GitOps provider on local Kind clusters (OCTR-749).
* Exempt `.terraform.lock.hcl`, `.terraform/`, and SSH keypairs from strict generator ownership checks.

### Infrastructure & Networking
* Calico: Support interface and CIDR autodetection modes (`OCTR-798`).
* Gateway API: Support `gateway.floating_ip` pinning and CoreDNS data-plane rewrites.
* CCM: Ensure `[LoadBalancer] subnet-id` is only emitted when `use_octavia` is disabled.
* Kubespray: Corrected node bind addresses, joined additional worker pools to Kubespray inventory, and enabled external cloud provider settings for kubelet.

### Platform Services & Storage
* Decouple service enablement rendering and unify Harbor certificate issuer.
* Allow filesystem storage for Harbor in lightweight and evaluation environments.
* Support Mimir S3 object storage configurations alongside OpenStack Swift (OCTR-784).
* Bump Keycloak to gitops-base `2026.03-rc4` with login theming and aligned OIDC security policies.

## Breaking and Compatibility Changes

* **Lifecycle Contract v3 Upgrade** -- Clusters initialized or deployed with rc07 target lifecycle contract v3 (`openCenter-gitops-base: 2026.03-rc05`). Older cluster configurations are automatically normalized to reference contract v3; running `cluster generate` updates OpenTofu module sources.
* **Cluster Promote Command Consolidated** -- The experimental `opencenter cluster promote` command has been consolidated into `opencenter cluster drift reconcile --to-config`.
* **Dedicated Secret Naming** -- Dedicated secrets are now named strictly based on their path. Run `opencenter secrets sync <name>` to materialize any missing secrets prior to validation.

## Upgrade from rc06

1. Update your openCenter CLI binary:

   ```bash
   mise run build
   ./bin/opencenter version
   ```

2. Validate existing cluster configurations to check for contract version alignment:

   ```bash
   ./bin/opencenter cluster validate <name>
   ```

3. Regenerate GitOps manifests to synchronize OpenTofu templates and module sources to contract v3:

   ```bash
   ./bin/opencenter cluster generate <name>
   ./bin/opencenter secrets sync <name>
   ```

4. Deploy or resume deployment:

   ```bash
   ./bin/opencenter cluster deploy <name>
   ```
