# openCenter CLI v1.0.0-rc08 -- Release Notes

> **Purpose:** For operators and platform engineers, lists features, fixes, migrations, and improvements shipped in openCenter CLI 1.0.0-rc08.

---

## Overview

The eighth release candidate for openCenter CLI 1.0.0 adds a generic Day-2 convergence workflow with the new `cluster reconcile` command, ships the official `scripts/install.sh` installer with manifest-derived checksum verification, deploys the OpenCenter Headlamp branding plugin, and resolves the OpenStack Cloud Controller Manager (CCM) load-balancer naming, subnet allocation, and upgrade-stall issues that affected rc07 deployments. The release also hardens the codebase and documentation pipeline: golangci-lint is enforced in CI and pre-commit (all 1,733 findings resolved, three latent bugs fixed), and every tracked documentation page was reconciled against the code and guarded against future drift.

This release contains 16 commits since rc07.

---

## Highlights

* **Cluster Reconcile (Day-2 Convergence)** -- New `opencenter cluster reconcile` and `cluster service reconcile` commands stage, validate, commit, and push GitOps changes, then trigger in-cluster Flux reconciliation for the affected sources, Kustomizations, and HelmReleases.
* **Official Installer** -- `scripts/install.sh` now exists and is the documented install path, with checksums taken from the release manifest (never self-computed), so a tampered plugin is refused instead of silently certified.
* **CCM Load-Balancer Correctness** -- `cluster.name` is rendered into openstack-ccm override values (preventing multi-cluster Octavia LB naming collisions) and `subnet-id` is emitted for all `use_octavia` modes, matching modern cloud-provider-openstack VIP allocation requirements.
* **No More CCM Upgrade Stalls** -- The CCM HelmRelease upgrade timeout rises to 9m with 3 remediation retries, ending permanent `Stalled=True` releases caused by slow one-node-at-a-time control-plane rollouts.
* **Headlamp Branding Plugin** -- `services.headlamp.branding_image` deploys a digest-pinned OpenCenter branding plugin with a forced theme that visitors cannot override.
* **Lint-Enforced Codebase** -- golangci-lint runs in CI and pre-commit; 1,733 findings resolved, surfacing three latent bugs including corrupt-backup tar trailers.
* **Documentation Reconciled and Guarded** -- Every Markdown page verified against code, schema, mise tasks, and the CLI surface, with new recurrence guards (stale-timestamp check, mise task coverage, CLI invocation verification via cobra completion).

## New Features and Improvements

### Cluster Reconcile: Day-2 GitOps Convergence

Two new commands close the loop between local manifest changes and live cluster state:

* **`opencenter cluster reconcile`** -- Generic convergence workflow: optionally re-renders/re-encrypts the target service overlay (`--generate`), scopes and stages cluster changes (validating that no unencrypted secrets are committed), commits and pushes to the GitOps remote, then triggers in-cluster Flux reconciliation for the GitRepository source, Kustomizations, and HelmReleases.
* **`opencenter cluster service reconcile <service>`** -- Service-scoped variant that maps a service to its Flux resources (`ResolveFluxServiceTarget`) and reconciles only that service's Kustomizations and HelmRelease.
* **Safety options** -- `--dry-run` previews the execution plan without mutating git or the cluster; `--push-only` commits and pushes without in-cluster Flux reconciliation.

  ```bash
  opencenter cluster reconcile opensnack/doritos --service openstack-ccm --generate
  opencenter cluster service reconcile headlamp --generate
  ```

* **OpenStack deploy push** -- `cluster deploy` now persists promoted network identity and pushes the re-rendered overlay before the CCM readiness gate, so network rebinding survives interrupted deployments.

### Installer Script

`scripts/install.sh` -- the install path the README and OpenStack walkthrough already instructed users to run -- now exists, with security behavior stronger than a naive installer:

* **Manifest-derived checksums** -- The plugin checksum registered in `<plugins-dir>/checksums.txt` comes from the release `checksums.txt` manifest, never from hashing the downloaded file. A tampered plugin is reported checksum-mismatch and refused.
* **Fail-closed verification** -- The manifest is fetched before binaries; a missing manifest is a hard error, so verification cannot silently no-op.
* **Single plugin location** -- The plugin installs only to `<plugins-dir>`, eliminating PATH-ordering ambiguity between duplicate copies.
* **Probed releases and tag resolution** -- Unknown versions exit non-zero even under `--dry-run`; both `v`-prefixed and bare tag forms resolve (`v1.0.0-rc07` and `1.0.0-rc06` both work).
* **Safe default paths** -- Defaults to `~/.local/bin` unless running as root, avoiding group-writable `/usr/local/bin` in shared images.

Full options and environment variables are documented in [Installation](../reference/installation.md).

### Headlamp Branding

* **Branding plugin deployment** -- New `services.headlamp.branding_image` field copies a digest-pinned OpenCenter branding plugin into Headlamp's plugins directory via a dedicated init container, coexisting with the upstream Flux UI plugin.
* **Forced theme** -- The plugin theme is forced (`--force-theme`), so branding cannot be undone by a visitor's localStorage preference -- Headlamp's Settings UI renders the theme picker even to anonymous visitors.
* **Dark mode default** -- The forced theme defaults to dark mode.

### OpenStack CCM Correctness

* **Cluster-scoped LB naming** -- `cluster.name` renders into openstack-ccm override values so `--cluster-name` matches the cluster, preventing Octavia load-balancer naming collisions across clusters sharing a project.
* **Always-on `subnet-id`** -- `subnet-id` is now emitted regardless of `use_octavia` mode: cloud-provider-openstack v1.36 uses Octavia exclusively and requires `subnet-id` for VIP allocation on multi-subnet projects.
* **Reliable re-render detection** -- Network output binding now checks whether the on-disk overlay actually lacks `subnet-id`, avoiding a two-step mutation skip that left stale overlays in place.
* **Load-balancer cleanup matching** -- The destroy-time ownership pattern now matches real CCM load-balancer names (`kube_service_<cluster>_*` and `kube_service_kubernetes_*`), so cluster-owned Octavia LBs are actually recognized and purged.

### GitOps Resilience

* **Force overwrite of tracked files** -- `--force` now permits overwriting modified tracked planned files during GitOps promotion, keeping backups of the previous content.
* **Umask drift auto-heal** -- Benign non-executable permission drift (0664 vs 0644) is normalized instead of failing the ownership preflight; `provider.tf` is enforced at 0644 during provisioning.
* **Deterministic preflight reporting** -- Existing repository paths are sorted before ownership preflight checks, so reports are stable across runs.

### Secrets and Deploy Preflight

* `--force` and `--skip-validation` now forward through post-sync manifest refresh (`secrets sync` → `cluster generate`), so a forced sync no longer dies on the validation it was told to skip.
* `--org` is supported in single-cluster `secrets sync`, and clusters are qualified by organization in multi-cluster sync.
* The `cluster deploy` secrets preflight remediation message now names the organization, producing a copy-pasteable command.

## Bug Fixes

### Cloud Controller Manager

* **CCM upgrade stalls** -- The openstack-ccm HelmRelease could go permanently `Stalled=True`: the 5m upstream upgrade timeout expired while the healthy `hostNetwork` rollout (maxUnavailable: 1, ~90s per control-plane node) finished 25 seconds later, and with zero retries plus no remaining diff, drift detection never re-attempted. The upgrade timeout is now 9m with 3 remediation retries; remediation deliberately never uninstalls or rolls back (that restores the `cloud-provider-uninitialized` taint and destroys diagnostic evidence). The parent Kustomization timeout is derived from the HelmRelease budget so the pair cannot drift apart.
* **CCM pod-security admission** -- The generated openstack-ccm namespace shipped without Pod Security Admission labels, so admission depended on whatever the cluster happened to enforce; baseline enforcement would reject CCM outright and stall bootstrap behind the component that clears the taint. Privileged service namespaces now render the full PSA trio (`enforce: privileged`, `warn`/`audit: baseline`).

### Backups

* **Corrupt archives fixed** -- A tar trailer was written after gzip finalization, producing corrupt backups; the lint sweep also surfaced discarded connectivity/provider validation errors and a duplicated `&&` operand in a test.

## Quality and Documentation

* **golangci-lint enforced** -- New `.golangci.yml` wired into CI (`test.yml` lint job) and pre-commit (gofmt + golangci-lint hooks). All 1,733 findings resolved: 10 unused funcs/types deleted, 2 ineffassign, 13 staticcheck, 39 govet, and 152 production errcheck sites fixed.
* **Documentation reconciled** -- Every tracked Markdown page reviewed against the code, schema, mise tasks, release assets, and CLI surface it describes. New installation reference page; service reference pages rebuilt from their Go structs; corrected tool pins, environment variables, walkthrough commands, and provider gates; zero reader-facing pages remain unreachable from the index.
* **Recurrence guards** -- Pre-commit rewrites `last_updated` on staged pages; CI fails pages whose timestamp predates the newest body change; a mise-task coverage checker and a CLI-invocation checker (verifying every documented command path against cobra completion -- `--help` silently succeeds for removed verbs) prevent phantom documentation from returning. Installer contract tests run against a stub release server, covering checksum registration, tamper rejection, and argument guards.
* **Reader-facing documentation set completed** for site publication: corrected provider/service references, new reconcile/error-code/release pages, refreshed index, and regenerated CLI reference.

## Breaking and Compatibility Changes

* **Go 1.27.3 required** -- The `go.mod` language floor is now 1.27.3 (the redundant `toolchain` line is dropped). Building from source requires Go 1.27.3; the mise pin matches.
* **CCM `subnet-id` always emitted** -- Rendered openstack-ccm configuration now includes `subnet-id` even when `use_octavia` is false, reversing the rc07 behavior. Clusters whose networks lack the bound subnet ID should re-run `cluster generate` after upgrading so network output binding repopulates it.
* **CCM namespace PSA labels** -- The openstack-ccm namespace now carries privileged Pod Security Admission labels. Clusters enforcing `baseline` cluster-wide previously rejected CCM pods; those deployments start working, but audit/warn entries for that namespace are expected.

## Upgrade from rc07

1. Update your openCenter CLI binary -- either re-run the installer or rebuild from source (Go 1.27.3 now required):

   ```bash
   curl -fsSL https://raw.githubusercontent.com/opencenter-cloud/openCenter-cli/main/scripts/install.sh | bash
   # or, from a checkout:
   mise run build
   ./bin/opencenter version
   ```

2. Re-render manifests so CCM override values pick up the cluster name, `subnet-id`, extended upgrade budget, and PSA labels:

   ```bash
   ./bin/opencenter cluster generate <name>
   ```

3. If a cluster is stuck on a stalled openstack-ccm HelmRelease from rc07, the new timeout/retry configuration plus a re-push resolves it via the new reconcile workflow:

   ```bash
   ./bin/opencenter cluster service reconcile openstack-ccm --generate
   ```

4. Deploy or resume deployment as usual:

   ```bash
   ./bin/opencenter cluster deploy <name>
   ```

* Air-gapped deployments require the companion `openCenter-AirGap` offline bundle.
